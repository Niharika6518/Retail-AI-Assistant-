# System Overview

The Retail AI Assistant is a simulation-based agentic AI system designed to support two primary retail workflows:

1. Personal Shopper (Revenue Agent)
2. Customer Support Assistant (Operations Agent)

The system combines:

- LLM reasoning
- Dynamic tool calling
- Deterministic business logic
- Grounded retrieval from structured data

The architecture separates reasoning from factual retrieval to reduce hallucinations and improve reliability.

---

# High-Level Architecture

```text
User Query
    ↓
LLM Agent (Groq + Llama 3.3)
    ↓
Dynamic Tool Selection
    ↓
Python Tools
    ↓
CSV Data + Policy Rules
    ↓
Tool Results
    ↓
LLM Final Response
```

---

# Core Components

## 1. Agent Layer

File:

```text
agent/retail_agent.py
```

### Responsibilities

- Receives user queries
- Sends prompts to the LLM
- Provides structured tool schemas
- Handles tool calling
- Executes tools dynamically
- Generates final user-facing responses

The LLM acts as the reasoning engine and decides which tool should be used based on the user request.

---

## 2. Tool Layer

Files:

```text
tools/product_tools.py
tools/order_tools.py
tools/return_tools.py
```

### Responsibilities

- Product retrieval
- Product filtering
- Order retrieval
- Return policy evaluation

The tool layer contains deterministic business logic and factual retrieval.

---

## 3. Data Layer

Files:

```text
data/product_inventory.csv
data/orders.csv
data/policy.txt
```

### Responsibilities

- Product inventory storage
- Order storage
- Return policy storage

All factual information is retrieved from structured data sources instead of being generated by the LLM.

---

# Tool Calling Design

The system uses structured tool calling to allow the LLM to dynamically decide which tool should be executed.

Implemented tools:

```text
search_products(filters)
get_product(product_id)
get_order(order_id)
evaluate_return(order_id)
```

The LLM determines:

- which tool to call
- when to call it
- what arguments to pass

This creates agentic behavior instead of hardcoded workflows.

---

# Personal Shopper Workflow

For shopping-related queries, the assistant:

1. Extracts user constraints
2. Calls `search_products()`
3. Filters by:
   - price
   - tags
   - size availability
   - stock availability
   - sale status
4. Sorts by bestseller score
5. Generates recommendation reasoning

### Example

```text
Need a modest evening gown under $300 in size 8 on sale
```

The assistant explains why the recommendation matches the user’s constraints instead of simply listing products.

---

# Customer Support Workflow

For support-related queries, the assistant:

1. Retrieves order information
2. Fetches related product data
3. Applies return policies
4. Evaluates eligibility deterministically
5. Explains the decision clearly

### Example

```text
Can I return order O0005?
```

The return decision is based on actual business rules rather than LLM guessing.

# Hallucination Prevention Strategy

Preventing hallucinations was one of the main architectural goals.

The system minimizes hallucinations using several strategies.

---

## 1. Grounded Retrieval

The assistant never invents:

- products
- inventory
- orders
- policies

All factual information comes directly from structured tools.

---

## 2. Deterministic Policy Logic

Return eligibility is evaluated using explicit Python logic instead of relying on the LLM.

This ensures:

- consistent decisions
- explainable reasoning
- reliable policy handling

---

## 3. Invalid Entity Handling

The system safely rejects:

- invalid order IDs
- invalid product IDs

instead of generating fabricated responses.

---

## 4. Separation of Responsibilities

The LLM handles:

- reasoning
- orchestration
- response generation

The tools handle:

- factual retrieval
- filtering
- business logic
- policy evaluation

This separation improves reliability and maintainability.

---

# Product Recommendation Logic

The shopping assistant evaluates multiple constraints simultaneously:

- tags/preferences
- price limits
- sale status
- requested size
- stock availability
- bestseller score

Products are ranked using bestseller score while respecting all user constraints.

---

# Return Evaluation Logic

The support assistant evaluates:

- return windows
- sale item rules
- clearance rules
- vendor-specific exceptions
- exchange rules

### Examples

- Clearance items are final sale
- Sale items receive store credit only
- Aurelia Couture supports exchanges only
- Nocturne has extended return windows

# Why This Architecture Was Chosen

This architecture was selected because it:

- separates reasoning from retrieval
- minimizes hallucinations
- improves explainability
- supports modularity
- mirrors real-world AI system design

The modular structure also makes it easy to extend the system with additional tools or data sources in the future.
